IQM Garnet · historical single-qubit calibration¶

5 & 15 September 2026 · 20 qubits · two independent calibration snapshots

This notebook documents the hardware context for experiments on composite pulses for π/2 rotations, with a focus on robustness to drive-frequency detuning and Rabi-amplitude errors. It visualizes the two quality-metric JSON files in source/. These are device benchmarks, not measurements of the composite sequences' error or robustness.

The five principal views use per-qubit dot plots: PRX gate error, T1, Ramsey T2, echo T2, and readout error. Directional readout errors are retained as supporting diagnostics. Two-qubit gates, couplers, QND/repeated-measurement metrics, and the separate Clifford benchmark are excluded.

The complete analysis runs offline after installing requirements.txt. The repository contains the source files, selected data in data/, and the executed notebook. No external service is needed to reproduce the plots. Static outputs remain visible on GitHub. Optional live controls appear near the end.

1. Scope, provenance, and units¶

The extracted JSON in data/ preserves the selected observations exactly: field names, values, units, uncertainty values, validity flags, observation IDs, and timestamps. It also retains calibration-set IDs, quality-metric-set IDs, and SHA-256 hashes of the source files in source/.

The readout family is measure_fidelity. The source files also contain metrics.ssro.measure.constant observations with different values; the two families are not combined. The PRX qualifier :par=d2 is preserved without inferring an undocumented meaning.

For an affine conversion y = a x + b, the reported uncertainty is converted as u(y) = |a| u(x). Error-plot uncertainties therefore have units of percentage points. The exports do not specify a confidence level or distribution. Whiskers below mean “± reported uncertainty”; they are not labeled as standard deviations or confidence intervals. No uncertainty is inferred from variation across qubits.

The snapshot dates come from the filenames. created_timestamp and end_timestamp describe the quality-metric records; they are not presented as job execution times or as evidence that a calibration remained constant during an experiment. Source timestamps without an offset remain unchanged. All 20 qubits are shown because an experiment-specific qubit subset is not encoded in these exports. Job-to-calibration matching requires the original job metadata.

3. Resonance-style graph view¶

Blue markers, numeric qubit order, a white background, and dashed grid lines make each qubit's reported value easy to compare. This first figure shows the 15 September snapshot. Error percentages start at zero. There are no lines between qubits: qubit number is an identifier, not a continuous experimental variable.

4. All five principal metrics, by date¶

Each row uses the same vertical scale for both snapshots, allowing direct visual comparison. Whiskers show the transformed uncertainty supplied with each observation. The dates are kept separate; no interpolation or time trend is inferred from two snapshots.

5. Directional readout errors¶

The selected readout fidelity is consistent, to numerical precision in both exports, with 1 − (p(0→1) + p(1→0))/2. The main readout-error figure uses the reported fidelity and its own reported uncertainty. The directional values below expose asymmetry; their uncertainties are not recombined under an assumed independence model.

8. Reproducibility and interpretation limits¶

  • The dataset contains 140 selected observations per snapshot from 360 source observations. Every retained field refers to exactly one qubit. Both complete source JSON files are included in source/.
  • extract_calibration.py recreates the selected JSON and CSV from the two files in source/. It uses an exact field allowlist, checks units, rejects duplicate metric/qubit entries, and preserves the source values. No field is selected solely because its name contains a qubit label.
  • reproduce.py executes this notebook in a fresh kernel, saves the executed notebook, and writes an offline HTML report. PNG and SVG figures are generated by this notebook. Paths are relative. Package versions used for verification are pinned in requirements.txt; the runtime versions are printed below.
  • PRX and readout error are distinct benchmarks. They must not be added or multiplied to claim a composite-sequence fidelity. The exports do not report detuning offsets, Rabi-amplitude errors, pulse durations, or a robustness curve.
  • T1 and T2 document relaxation/coherence context. They do not determine a unique dephasing rate or the performance of a driven composite sequence here.
  • Two snapshots do not establish continuous hardware stability or a causal explanation for a change in experiment results. Their applicability to a particular run depends on its calibration-set ID and execution metadata.
